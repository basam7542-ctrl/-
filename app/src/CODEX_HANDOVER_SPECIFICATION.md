## 1. ملخص المشروع والغرض التقني (Executive Technical Summary)

هذا المشروع عبارة عن تطبيق أندرويد متكامل وتجاري حقيقي لإدارة مبيعات ومخازن وفواتير وحسابات **«معرض البشيري للأجهزة الكهربائية»**.  
تمت كتابة الكود المصدري بالكامل بلغة **Kotlin** مع أحدث مكتبات **Jetpack Compose** للواجهات و **Room Database (SQLite)** لحفظ ومعالجة البيانات محلياً مع الاستعداد الكامل للمزامنة السحابية عبر **Firebase Firestore**.

التطبيق ليس مجرد نموذج واجهة (UI Mockup) أو عرض شكلي؛ بل هو تطبيق عملي يعمل على أرض الواقع في المعرض:
- إدارة المخزون بخصم فوري للكميات عند البيع.
- فواتير بيع متعددة الأصناف مع تفاصيل العميل والهاتف والخصم والمتبقي.
- طباعة حرارية لاسلكية متوافقة مع طابعات البلوتوث (ESC/POS 80mm/58mm).
- مساعد صوتي مدمج «بشير» ينفذ الأوامر الفورية باللغة العربية.
- تجربة بصرية سينمائية ثلاثية الأبعاد مستوحاة من النظام الشمسي والأرض المستقبلية (**BESHEER COSMIC FUTURE**).

## 3. قاعدة البيانات وبنية الكيانات (Room Database & Entity Schema)

قاعدة البيانات المحلية تستخدم **Room Database (SQLite)**، ومثبتة في الإصدار رقم `14` في ملف `AppDatabase.kt`.

### الكيانات الرئيسية (Entities):
1. **`UserAccountEntity` (جدول `user_accounts`):**
   - `id`: المعرف (`admin`, `seller1`, `seller2`, `seller3`).
   - `displayName`: الاسم الظاهر.
   - `role`: الدور (`ADMIN` أو `SELLER`).
   - `pin`: رمز المرور المكون من 4 أرقام.
2. **`CategoryEntity` (جدول `categories`):**
   - الأقسام الرئيسية (ثلاجات، غسالات، شاشات، بوتاجازات، ميكروويف، تكييفات، دفايات، إلخ).
3. **`BrandEntity` (جدول `brands`):**
   - الشركات والماركات التجارية التابعة للأقسام (توشيبا، شارب، إل جي، بيكو، تورنيدو، سامسونج، إلخ).
4. **`ProductEntity` (جدول `products`):**
   - المنتجات الأساسية الرابطة بين القسم والماركة.
5. **`ProductModelEntity` (جدول `product_models`):**
   - قلب المخزون والأسعار:
     - `modelName`: اسم وتوصيف الموديل (مثال: "18 قدم نوفروست إنفرتر").
     - `finalPrice`: سعر البيع للجمهور.
     - `minAllowedPrice`: الحد الأدنى المسموح للبائع بالتفاوض عنده (يمنع البيع بخسارة).
     - `stockQuantity`: الكمية المتوفرة بالمخزن.
     - `code`: الباركود أو كود الموديل.
6. **`InvoiceEntity` و `InvoiceItemEntity` (جدول الفواتير متعددة الأصناف):**
   - يدعم رأس الفاتورة وتفاصيل المنتجات (`InvoiceWithItems` عبر علاقة `@Relation`).
7. **`SaleRecordEntity` (جدول `sales_records`):**
   - سجل المبيعات السريعة الفردية.
8. **`CustomerAccountEntity` و `SupplierAccountEntity` و `MerchantAccountEntity`:**
   - الحسابات والأرصدة المدينة والدائنة ومعاملات السداد والتحصيل.
9. **`ExpenseRecordEntity` و `TreasuryTransactionEntity`:**
   - حركة الخزينة والمصروفات وحساب السيولة النقدية.
10. **`DamageRecordEntity` و `ReturnRecordEntity`:**
    - سجلات البضائع التالفة والمرتجعة.

## 4. نظام الصلاحيات والحسابات (RBAC & User Security)

التطبيق يفصل بصرامة بين المدير والبائعين عبر الحقل `role`:
- **المدير (`ADMIN`):**
  - الوصول الكامل لجميع الكواكب والأقسام.
  - إضافة وتعديل وحذف الأقسام والماركات والموديلات.
  - تعديل الأسعار والحد الأدنى للبيع.
  - الاطلاع على تقارير الأرباح والخزينة والمصروفات.
  - جرد المخزون والنسخ الاحتياطي واستعادة المحذوفات.
- **البائعون (`SELLER`):**
  - صلاحية إنشاء الفواتير والمبيعات السريعة.
  - الاستعلام عن الموديلات والأسعار والأرصدة المتاحة.
  - محمي من تعديل الأسعار دون الحد الأدنى (`minAllowedPrice`).
  - محجوب عنه تفاصيل تكلفة الشراء، وأرباح المعرض، وسجلات الإدارة الحساسة.

## 5. محرك النظام الشمسي والتأثيرات السينمائية (Cosmic Engine Specs)

### أ. النظام الشمسي (`CosmicSolarSystemScreen.kt`):
- يتم حساب إحداثيات الكواكب على مسارات بيضاوية حول الشمس المركزية باستخدام معادلات الجيب وجيب التمام:
  ```kotlin
  x = centerX + orbitRadiusX * cos(angle)
  y = centerY + orbitRadiusY * sin(angle)
  ```
- **الشمس المركزية:** تستخدم رسمة عالية الدقة `cosmic_sun_core.png` مع حركة نبض ضوئي دورانية عبر `rememberInfiniteTransition`.
- **أفق الأرض:** مرسوم في أسفل الشاشة عبر `cosmic_earth_horizon.png` مع تأثير الغلاف الجوي وأضواء المدن.
- **زر بشير:** في المنتصف السفلي محاط بتموجات صوتية متغيرة الطول عبر مقياس `rmsLevel` و `waveAlpha`.

### ب. الانتقال السينمائي ثلاثي الأبعاد (`CosmicPlanetaryTransitionOverlay.kt`):
- عند النقر على كوكب المنتجات، تتغير الحالة إلى `isZoomingIntoProducts = true`.
- يقوم `Animatable` بتحريك المقياس (`scale`) من `1.0f` إلى `5.5f`، وزاوية الدوران بمقدار `22` درجة خلال `650ms` بانحناء `FastOutSlowInEasing`.
- يتم إذابة الغلاف الجوي (`overlayAlpha`) ليظهر كوكب المنتجات المستوحى من الأرض دون حدوث قفزة بصرية مفاجئة.
- الانتقال العكسي عند الضغط على زر الرجوع `<` يعيد الكاميرا من `5.5f` إلى `1.0f` لتهبط في مدار النظام الشمسي مجدداً.

## 6. المساعد الصوتي الذكي «بشير» (Voice Assistant Pipeline)

1. **الالتقاط الصوتي:** يتم عبر واجهة `SpeechRecognizerHelper` المعتمدة على محرك جوجل للتعرف على الصوت باللغة العربية (`ar-EG`).
2. **التحليل الدلالي للأوامر (`BasheerVoiceParser.kt`):**
   - يدعم الأوامر الطبيعية مثل:
     - *"سعر شاشة توشيبا 43 كام؟"* -> يستخرج الموديل ويعرض سعره.
     - *"عاوز أبيع غسالة شارب"* -> يفتح نافذة البيع فوراً.
     - *"رصيد الخزنة دلوقتي كام؟"* -> يجلب رصيد الخزينة الفعلي.
     - *"سجل مصروف 150 جنيه بوفيه"* -> يسجل المصروف ويخصمه من الخزينة بعد التأكيد.
     - *"افتح المخزون"* أو *"افتح الفواتير"* -> ينتقل للشاشة المطلوبة.
3. **الرد الصوتي (TTS):** عبر محرك `TtsHelper` باللغة العربية.
4. **المظهر الفضائي:** نافذة الحوار مزودة بنواة مغناطيسية هولوجرافية (`cosmic_bashir_orb.png`).

## 8. توثيق المزامنة السحابية و Firebase (Cloud Synchronization)

التطبيق مهيأ بملف `app/google-services.json` للاتصال بـ **Firebase**:
- **قاعدة البيانات السحابية المقترحة:** Cloud Firestore.
- **قواعد الأمان (Firestore Rules Blueprint):**
  ```javascript
  rules_version = '2';
  service cloud.firestore {
    match /databases/{database}/documents {
      match /stores/{storeId}/products/{productId} {
        allow read: if request.auth != null;
        allow write: if request.auth != null && request.auth.token.role == 'ADMIN';
      }
      match /stores/{storeId}/invoices/{invoiceId} {
        allow read, write: if request.auth != null;
      }
    }
  }
  ```
- **ملاحظة أمنية:** لا توجد أي مفاتيح خاصة أو أسرار حساسة مسجلة داخل الكود البرمجي؛ وتتم قراءة أي مفاتيح عبر `BuildConfig` وبيئة النظام الآمنة.

## 9. البيانات الحقيقية مقابل البيانات التجريبية (Data Integrity Audit)

- **المنتجات، الموديلات، والأسعار:** بيانات حقيقية 100% تُقرأ وتُكتب في جدول SQLite عبر Room.
- **المخزون والأرصدة:** حقيقية 100%؛ أي عملية بيع تخصم فوراً من `stockQuantity`.
- **الفواتير والمبيعات:** حقيقية 100%؛ تسجل بأرقام تسلسلية وتواريخ حقيقية.
- **حسابات العملاء والموردين:** حقيقية 100% مرتبطة بالخزينة.
- **لا توجد أي بيانات وهمية أو صور ثابتة بديلة للوظائف البرمجية.**

## 11. إرشادات لـ Codex عند استكمال التطوير (Codex Extension Guide)

عند طلب إضافة مراحل جديدة أو توسيع الكواكب الأخرى:
1. **عدم كسر قاعدة البيانات:** أي إضافة في جداول Room تتطلب زيادة إصدار قاعدة البيانات في `AppDatabase(version = 15)` مع إضافة ملف الهجرة أو `fallbackToDestructiveMigration()` بحذر.
2. **إضافة كوكب جديد للمرحلة الثانية:**
   - قم بإنشاء شاشة الكوكب في حزمة `ui/screens/cosmic/` (مثل `CosmicInventoryPlanetScreen.kt`).
   - أضف حالة الانتقال في `MainActivity.kt` بنفس أسلوب `isZoomingIntoProducts`.
   - اربط أحداث الضغط في `CosmicSolarSystemScreen.kt`.
3. **الحفاظ على خط Cairo:** دائماً استخدم `fontFamily = CairoFontFamily` لكافة النصوص العربية لضمان تجانس الهوية.
4. **منطقة الأمان (Safe Area):** استخدم دائماً `WindowInsets.statusBars` و `WindowInsets.navigationBars` لمنع تداخل العناصر مع حواف الهاتف.
